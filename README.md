# 청약한눈

아파트, 공공임대, 오피스텔 청약 공고를 한곳에서 검색하고 일정과 핵심 자격을 확인하는 서비스입니다.

## 프로젝트 구성

    cheongyak-one
    ├── frontend   React + TypeScript + Vite
    └── backend    Java 21 + Spring Boot + JPA + PostgreSQL + Flyway

로컬에서는 프런트엔드와 백엔드를 각각 실행합니다. 운영에서는 React 정적 파일을 S3·CloudFront에, Spring Boot API를 Elastic Beanstalk에 분리 배포합니다.

AWS 운영 배포는 Elastic Beanstalk, RDS PostgreSQL, 비공개 S3, CloudFront, GitHub OIDC로 구성됩니다. 인프라 생성과 배포 순서는 [AWS 배포 가이드](docs/aws-deployment.md)를 참고합니다.

공개 테스트에서는 기존 코드 구조를 유지한 [Vercel + Render + Supabase 배포 가이드](docs/vercel-render-supabase-deployment.md)를 사용할 수 있습니다. GitHub `main`을 각 서비스에 연결하면 자동 배포하며, 실제 클라우드 리소스 생성은 가이드의 계정 설정 단계에서만 수행합니다.

## 로컬 실행

### Codex 개발 하네스

저장소 루트에서 `node scripts/harness.mjs doctor`로 도구를 확인하고,
수정 중에는 관련 테스트만 실행하고, 변경과 기록을 모은 뒤 최종 전체 검증을 수행합니다. `node scripts/harness.mjs plan`으로 범위를 확인한 뒤 앱 변경은 `verify --scope full`(UI/모바일·인증은 `--extended`), 문서만 변경하면 docs 범위를 사용합니다.
작업 규칙은 [AGENTS.md](AGENTS.md), 상세 적용·사용법은 [하네스 가이드](docs/HARNESS.md)를 참고합니다.
하네스는 commit/push/PR/배포를 자동 실행하지 않습니다.
단일·멀티 에이전트는 작업에 맞춰 자동 선택합니다. 역할 설정과 적용 확인은 [멀티 에이전트 가이드](docs/MULTI_AGENT.md)를 참고하세요. 실제 위임에는 해당 런타임의 서브에이전트 지원이 필요합니다.

### 프런트엔드

    cd frontend
    npm install
    npm run dev

기본 주소는 http://localhost:5173 이며 /api 요청은 http://localhost:8080 으로 전달합니다.

### 백엔드

PostgreSQL 연결 전에는 PostgreSQL 호환 모드의 H2 기반 local 프로필을 사용할 수 있습니다.

    mvn -pl backend spring-boot:run -Dspring-boot.run.profiles=local

운영과 유사한 PostgreSQL 환경에서는 .env.example을 참고해 환경변수를 등록하고 실행합니다.

    mvn -pl backend clean package
    java -jar backend/target/cheongyak-one-backend-0.1.0-SNAPSHOT.jar

## 데이터베이스 변경

- JPA는 ddl-auto=validate로 사용합니다.
- 테이블 생성과 변경은 backend/src/main/resources/db/migration의 Flyway SQL로 관리합니다.
- 이미 적용한 Migration 파일을 수정하지 않고 다음 버전 파일을 추가합니다.

## 일배치

- 기본 실행 시각: 매일 03:10 (Asia/Seoul)
- 최근 90일과 향후 365일 공고를 재조회합니다.
- 한국부동산원 청약홈 API에서 APT와 오피스텔 공고를 페이지 단위로 수집합니다.
- 마이홈포털 API 키가 설정된 환경에서는 공공임대 모집공고도 함께 수집합니다.
- 마이홈포털 API 키가 없으면 공공임대 수집만 건너뛰고 청약홈 APT·오피스텔 배치는 계속 실행합니다.
- 각 공고 소스는 기본 3회까지 재시도하며, 한 소스가 최종 실패해도 다른 소스의 수집과 저장은 계속합니다.
- 일부 소스만 실패한 실행은 관리자 운영 화면에 `부분 성공`으로 기록됩니다.
- 실행 이력은 SYNC_EXECUTION에 기록합니다.
- 소스별 실행 결과는 SOURCE_SYNC_EXECUTION에 기록하며 조회·저장·저장 실패·주택형 실패·주택형 빈 응답을 구분합니다. 빈 응답은 자료가 없다는 의미이며 삭제나 실패로 간주하지 않습니다.
- 공개 `GET /api/v1/notices/freshness`와 운영 관리 화면은 아파트·오피스텔·공공임대의 마지막 성공 시각을 각각 표시합니다. 설정된 모든 소스가 30시간 이내에 성공해야 전체를 최신으로 표시하며, 최근 부분 실패는 다른 소스의 성공으로 가려지지 않습니다. 미설정 소스는 별도로 표시하고, 소스별 기록을 도입하기 전의 전체 이력으로 성공 시각을 추정하지 않습니다.
- 관리자는 `POST /api/v1/admin/sync-executions?source=REB_APT`처럼 한 소스를 선택해 공고·주택형을 재수집할 수 있습니다. 기존 관리자·CSRF 검사와 중복 실행 제한을 동일하게 적용합니다.

### 배포 후 자동 검증

- CI는 Chromium 전체 흐름과 iPhone WebKit의 검색·상세·관심 저장·오프라인 복구 흐름을 실행하고 보고서와 실패 추적 자료를 7일 보관합니다.
- `main`의 CI 성공 후 `Verify production deployment`가 Vercel과 Render의 공개 버전 정보를 최대 12분 기다립니다. 두 서비스가 해당 커밋으로 바뀐 뒤 페이지·헬스·최신성·인증 경계를 검사하며, 이전 버전의 정상 응답은 통과시키지 않습니다.
- 운영 프런트엔드의 `/release.json`은 Vercel 빌드 커밋을, API의 `/api/v1/release`는 Render 실행 커밋을 제공합니다. 확인할 수 없는 환경은 `unknown`이며 운영 검증을 통과하지 않습니다.
- 검사 시도별 결과는 GitHub Actions의 `production-verification-*` JSON 아티팩트로 14일 보관합니다. 배포 지연·응답 오류도 결과에 남기며 워크플로를 실패 처리합니다. 토큰·회원 쿠키·데이터 변경 없이 공개 응답만 확인합니다.
- 수동 재검사는 `Verify production deployment`의 `Run workflow`를 `main`에서 실행합니다. 로컬에서는 `node scripts/verify-deployment.mjs <frontend-origin> <api-origin> <40자리 커밋 SHA>`로 같은 검사를 실행할 수 있습니다.

GitHub Actions의 `CI / real-data` 작업은 Repository Secret인 `REB_API_KEY`를 환경변수로 주입합니다. PostgreSQL 구성 전에는 H2에 실제 공고를 저장하고 공개 데이터만 `reb-real-data-sample` 아티팩트로 출력합니다.

프런트엔드는 더 이상 예시 공고를 사용하지 않습니다. 백엔드의 `/api/v1/notices` 목록·상세 API를 호출하며, 개발 서버에서는 Vite 프록시가 `localhost:8080`의 Spring Boot로 요청을 전달합니다. 첫 화면은 접수중·오픈 예정 공고를 우선 표시하며 `마감 공고 포함`을 켜면 지난 공고도 조회합니다. 검색·지역·유형·상태·정렬은 서버에서 처리하고, 최신·마감 임박·접수 시작일·당첨 발표일·낮은 분양가·공급 세대 기준 정렬을 제공합니다. 프런트는 첫 12건을 우선 표시한 뒤 다음 페이지를 요청합니다. 같은 탭에서는 최근 10분 이내에 본 목록을 임시로 보관해 Render Free 인스턴스 기동 중에도 먼저 표시합니다.

목록 API는 저장된 공급기관·사업주체(`businessEntityName`)를 포함해 상세 클릭 전부터 카드에 표시합니다. 기관명이 없는 공고는 `공고문 확인`으로 안내합니다. 상세 API는 목록용 요약 응답과 분리되어 공급 구분, 입주 예정월, 특별공급·계약 일정, 시공사, 문의처, 분양 홈페이지를 추가로 제공합니다. 외부 API의 링크는 HTTP·HTTPS 주소만 저장합니다.

서버 기동 지연이나 일시적인 연결 오류가 발생하면 공고 목록과 상태별 건수를 각각 최대 약 5분 동안 자동 재시도합니다. 아직 확인하지 못한 건수는 `–`로 표시하며, 집계 조회가 최종 실패해도 공고 목록을 계속 탐색하고 `건수 다시 불러오기`로 재요청할 수 있습니다. 검색 조건을 바꾸면 이전 집계 요청과 재시도를 취소합니다.

### 공고 검토 기능

검색 목록·상태별 건수·회원 추천·저장 조건의 새 공고 알림은 같은 공급 구분·지역·예산·공급면적 판정 규칙을 사용합니다. 예산과 면적을 함께 지정하면 **동일한 주택형**이 두 범위를 모두 만족해야 합니다. 예산은 공개된 주택형별 최고 공급금액으로 비교하며, 경계값을 포함합니다. 주택형 정보가 없는 공고는 예산만 지정했을 때 공고의 최저~최고 금액 구간으로 판정합니다. 면적 조건이 있거나 주택형의 필요한 값이 미확인인 경우에는 일치로 처리하지 않습니다. 상세 표에는 전체 주택형을 유지하면서 현재 검색 조건에 맞는 행을 표시합니다.

- 공고를 최신 공고순 또는 마감 임박순으로 정렬할 수 있습니다.
- 최대 3개 공고를 지역·일정·가격·공급 규모 기준으로 비교할 수 있습니다.
- 비교 목록은 브라우저에 저장되며 URL의 `compare` 값으로 공유할 수 있습니다.
- 로그인 회원의 비교 목록은 계정에 저장되어 다른 기기에서도 이어서 확인할 수 있습니다.
- 로그인할 때 현재 브라우저 또는 공유 링크의 비교 목록을 계정 목록과 합치며 최대 3개를 유지합니다.
- 관심 공고 또는 비교 공고의 접수 시작·마감·당첨 발표 일정을 `.ics` 파일로 저장할 수 있습니다.
- 상세 공고 URL을 복사해 공유할 수 있으며 직접 접속·새로고침·브라우저 뒤로가기로 상세 화면 상태를 복원합니다.
- 최근 확인한 공고 5건을 브라우저에 보관해 홈에서 빠르게 다시 열 수 있으며 언제든 전체 삭제할 수 있습니다.
- 검색어·상태·지역·주택유형·정렬 조건을 URL로 공유하고 새로고침이나 브라우저 탐색 후에도 복원합니다.
- 캘린더 파일은 브라우저에서 생성하며 서버로 개인 일정을 전송하지 않습니다.

### 회원 기능

- 이메일 회원가입과 HttpOnly 세션 쿠키 기반 로그인을 지원합니다.
- 회원가입은 계정 정보와 맞춤 정보의 2단계 화면으로 구성되며, 생년월일·성별·혼인 상태·가구원 수·자녀 수·거주 지역을 선택 입력할 수 있습니다.
- 맞춤 정보는 별도 수집·이용 동의가 있을 때만 저장하며 공고 추천, 자격 사전점검 보조, 서비스 이용 통계 및 추천 품질 개선에 사용합니다. 동의 시점과 문구 버전을 기록하고, 계정 화면에서 닉네임과 계정은 유지한 채 선택정보와 동의 이력만 즉시 삭제할 수 있습니다.
- 성별은 추천 점수나 청약 자격 판정에 사용하지 않으며, 관리자 회원 통계에서 동의 회원의 연령대·혼인 상태·거주 지역·가구원·자녀 수와 함께 집계값으로만 제공합니다. 관리자 회원 목록에는 개인별 맞춤정보를 노출하지 않습니다.
- 선택형 맞춤 정보는 회원 관리 화면에서 수정·삭제할 수 있고, 거주 지역은 검색 지역을 별도로 지정하지 않았을 때 추천 점수의 보조 신호로만 사용합니다.
- 이메일 인증 링크는 24시간 동안 한 번만 사용할 수 있으며, 인증 전 로그인은 차단됩니다.
- 비밀번호 재설정 링크는 30분 동안 한 번만 사용할 수 있고 완료 시 모든 기기에서 로그아웃됩니다.
- 인증·재설정 토큰은 원문 대신 SHA-256 해시만 DB에 저장하며 재요청에는 2분 제한을 둡니다.
- 비밀번호는 BCrypt로 저장하고, 5회 연속 실패하면 10분 동안 로그인을 잠급니다.
- 닉네임·비밀번호 변경, 로그아웃, 회원 탈퇴를 지원합니다.
- 로그인 전 브라우저에 저장한 관심청약은 첫 로그인 시 계정 목록과 합쳐집니다.
- 비밀번호 변경과 탈퇴 시 모든 기기의 로그인 세션을 폐기합니다.
- 회원관리에서 로그인한 브라우저·운영체제와 로그인 시각을 확인하고 다른 기기를 개별 또는 일괄 종료할 수 있습니다.
- 계정당 활성 로그인은 최근 10개로 제한하며, 초과 시 가장 오래된 세션부터 종료합니다.
- 기기 관리에는 IP 주소를 저장하지 않으며, 회원가입과 비밀번호 변경 화면에서 비밀번호 확인을 검증합니다.
- 탈퇴한 회원의 개인정보와 맞춤 프로필은 제거·익명화하고 관심청약은 삭제합니다.
- 상태 변경 요청은 세션별 CSRF 토큰으로 검증합니다.

### 맞춤 검색조건

- 로그인 회원은 지역·주택유형·공고상태·정렬 조건을 계정에 저장할 수 있습니다.
- 저장한 조건은 로그인 시 자동으로 적용되며 다른 기기에서도 불러올 수 있습니다.
- 필터 화면에서 현재 조건으로 덮어쓰거나 저장 조건을 삭제할 수 있습니다.

### 관심청약 알림

- 관심청약의 접수 시작일, 마감 7일·3일·1일 전, 당첨자 발표일 알림을 제공합니다.
- 알림 생성 작업은 기본적으로 매시 5분에 실행되며 같은 일정의 알림은 중복 생성하지 않습니다.
- 헤더 알림함에서 미읽음 개수 확인, 개별 읽음, 모두 읽음과 공고 상세 이동을 지원합니다.
- 회원별로 받을 일정 종류를 설정할 수 있고, 관심 해제 시 해당 공고 알림도 삭제됩니다.
- 저장한 지역·주택유형·접수상태에 맞는 신규 공고도 관심 등록 전부터 알림으로 받을 수 있습니다.
- 관심 등록한 공고의 일정·주소·공급 규모·문의처 등 주요 정보가 바뀌면 변경 알림을 받을 수 있습니다.
- 상세 화면에는 최근 변경 시각과 변경 항목을 함께 표시해 다시 확인할 부분을 바로 알 수 있습니다.
- 변경 기록은 최근 20건까지 시간순으로 보관해 상세 화면에서 확인할 수 있습니다.
- 공고의 최초 수집 시각을 별도로 보존해 이후 정보 갱신 때 신규 공고 알림이 반복되지 않습니다.
- 회원이 직접 동의하면 인증한 이메일로도 선택한 일정·신규 공고 알림을 발송합니다. 기본값은 수신 안 함입니다.
- 이메일 발송 상태는 DB에 저장하며 실패 시 1·2·4·8·16분 간격으로 최대 5회 재시도합니다.
- 하이브리드 앱은 로그인 후 FCM 기기 토큰을 `PUT /api/v1/members/me/device-tokens`로 등록하고, 로그아웃·알림 권한 해제 시 `DELETE /api/v1/members/me/device-tokens`로 해제합니다. iOS/Android 토큰과 앱 푸시 수신 동의는 회원별로 분리해 저장합니다.
- FCM 발송은 `MEMBER_PUSH_DELIVERY=fcm`, `MEMBER_PUSH_FCM_SERVICE_ACCOUNT_BASE64=<서비스 계정 JSON의 Base64>`로 활성화합니다. 앱은 `notificationId`, `noticeId`, `type`, `deepLink`(`cheongyakone://notices/{noticeId}`) 데이터를 받아 해당 공고 상세로 이동합니다. 발송은 알림 생성과 분리해 처리하고 실패 시 1·2·4·8·16분 간격으로 최대 5회 재시도하며, 만료·해제 토큰은 자동 삭제합니다. 웹 브라우저 푸시는 사용하지 않습니다.
- 읽은 지 90일이 지난 알림은 자동 삭제합니다.
- 로그인 중에는 헤더의 미읽음 개수를 1분마다 갱신하고, 열린 알림함은 30초마다 자동 갱신합니다.
- 알림함에서 마지막 확인 시각과 수동 새로고침을 제공합니다.

### 맞춤 청약 추천

- 회원이 저장한 지역·주택유형·접수상태를 기준으로 접수 예정·접수중 공고를 추천합니다.
- 조건 일치도와 접수 시작·마감 임박도를 점수화하고 추천 이유를 함께 표시합니다.
- 추천 결과는 최대 6건이며 마감된 공고와 저장 조건에 맞지 않는 공고는 제외합니다.
- 저장 조건이 없거나 결과가 없으면 조건을 설정하거나 넓힐 수 있도록 안내합니다.
- 추천 점수는 검색 편의를 위한 값이며 실제 청약 자격 판정 결과가 아닙니다.
- 원하지 않는 공고는 추천에서 숨길 수 있고, 계정에 저장된 숨김 목록을 한 번에 초기화할 수 있습니다.
- 숨긴 공고를 관심청약으로 저장하면 최신 선택을 우선해 추천 숨김 상태가 자동 해제됩니다.

- 무주택 세대, 청약통장, 신혼부부·생애최초 공급에 관한 답변을 바탕으로 공식 공고문에서 확인할 항목을 정리합니다.

- 신청 가능·불가능을 판정하거나 보장하지 않으며 저장 버튼을 누르기 전에는 답변을 서버로 전송하지 않습니다.
- 로그인 회원은 답변을 계정에 저장하고 다른 기기에서 조회·수정하거나 삭제할 수 있습니다.

## 환경변수

### OpenAI 청약 상담 (기본 비활성화)

상세 화면에서 로그인한 회원이 자격·필요 현금·가점의 **확인 항목**을 요청할 수 있다.
주택형(최대 20건), 원 단위 공급금액, 공급 세대, 특별공급·접수·발표·계약 일정을 확인된 근거로 제공하고,
답변의 `[F1]` 같은 번호에서 해당 자료를 바로 확인할 수 있다. 미확인 자료와 생략된 주택형은 별도로 표시한다.
공식 공고문 원문은 가져오지 않으며 근거 번호 검사는 사실 정확도를 보장하지 않는다.
금액·비율·가점은 모델 본문에서 재계산하지 않고 서버가 제공한 근거에 표시한다.
이는 자격 판정, 개인별 가점 계산, 대출 또는 필요 현금의 확정 견적이 아니다.
서버의 Responses API가 공개 공고와 선택한 주제만 전송하며 회원 프로필·연락처·세션은 전송하지 않는다.
전송 동의가 필요하고 상담 내용은 앱 DB에 저장하지 않는다. `store: false`는 OpenAI 응답 저장을 끄는 옵션이며
제공자의 모든 데이터 보관을 없앤다는 뜻은 아니다.

- 서버 환경변수: `AI_CONSULTATION_ENABLED` (기본 `false`), `OPENAI_API_KEY`, `OPENAI_MODEL`.
- 모델명은 운영자가 접근 권한과 비용을 확인한 GPT 모델 ID로 설정한다. 키를 `VITE_*` 환경변수에 넣지 않는다.
- 활성화했는데 키나 모델명이 비어 있으면 서버가 시작되지 않는다.
- 회원당 15분 3회, 서비스 전체 시간당 100회, 동시 2회로 제한한다. 실패 요청도 횟수에 포함한다.
  DB 기록과 짧은 잠금으로 서버 재시작·여러 인스턴스에 걸쳐 제한을 공유한다. 제공자 호출 동안 DB 잠금을 유지하지 않는다.
- 호출은 자동 재시도하지 않는다. 서버 60초, 화면 75초 제한이며 화면 취소가 이미 시작된 공급사 호출을 취소하지는 않는다.
- 로컬/CI는 모의 응답만 사용한다. 운영 키 설정과 유료 호출은 별도 활성화 절차다.

### 알림 채널 연결 상태

앱 푸시는 기존 FCM 발송기를 사용한다. 발송 비활성화 중에는 대기 알림을 성공 처리하지 않는다.
알림 설정 화면에 SMTP 설정 및 FCM 설정·기기 등록 상태를 표시하며 이는 최종 기기 수신 확인을 뜻하지 않는다.
문자·알림톡은 업체가 아직 정해지지 않아 실제 어댑터가 없고, 환경변수만 넣어도 활성화되지 않는다.
연결 전 발신번호/카카오 채널·승인 템플릿, 수신번호 검증·동의, 업체별 인증·콜백·중복방지 계약을 확정해야 한다.

실제 DB 비밀번호와 API 키는 Git에 커밋하지 않습니다.

| 이름 | 설명 |
|---|---|
| DB_URL | PostgreSQL JDBC URL |
| DB_USERNAME | 애플리케이션 DB 계정 |
| DB_PASSWORD | 애플리케이션 DB 비밀번호 |
| REB_API_KEY | 한국부동산원 청약홈 API 키 |
| MYHOME_API_KEY | 마이홈포털 API 키 |
| NOTICE_SYNC_RUN_ON_STARTUP | `true`일 때만 서버 기동 직후 전체 공고·주택형 동기화를 실행한다. Render 공개 테스트 기본값은 `false`이며, 일일 GitHub Actions 동기화를 사용한다. |
| NOTICE_SYNC_CRON | 공고 동기화 실행 시각 |
| MEMBER_NOTIFICATION_CRON | 관심청약 알림 생성 시각(기본: 매시 5분) |
| MEMBER_NOTIFICATION_EMAIL_CRON | 대기 중인 알림 이메일 발송 시각(기본: 5분마다) |
| MEMBER_MAIL_DELIVERY | 회원 메일 전달 방식(`log`, `smtp`, `disabled`) |

| FRONTEND_BASE_URL | 인증·재설정 링크에 사용할 프런트 주소 |
| MEMBER_MAIL_FROM | 발신 이메일 주소 |
| SMTP_HOST / SMTP_PORT | SMTP 서버 주소와 포트 |
| SMTP_USERNAME / SMTP_PASSWORD | SMTP 자격정보 |

로컬 기본값은 `log`이며 인증·재설정 링크가 백엔드 로그에 출력됩니다. 실제 운영에서는 SMTP 설정을 완료하기 전까지 AWS 프로필의 인증 필수 기본값이 꺼져 있습니다.

### AI 비용·품질 운영 지표

- 관리자 `AI 사용량`에 최근 7일(한국 시간)의 모델별 입력·캐시 입력·출력 토큰, 평균 처리시간, 실패 유형을 표시한다. 캐시 입력은 전체 입력에 포함된 값이다.
- 제공자 응답의 실제 사용량 메타데이터만 기록한다. 누락·잘못된 사용량과 과거 기록은 미확인으로 표시한다. 미완료·거절·답변 검사 실패라도 확인된 토큰과 예상비용은 기록한다. 프롬프트·답변·제공자 응답 ID는 저장하지 않으며 기록은 30일 보관한다.
- `AI_PRICED_MODEL`에 요청 모델명을, `AI_INPUT_USD_PER_MILLION`, `AI_CACHED_INPUT_USD_PER_MILLION`, `AI_OUTPUT_USD_PER_MILLION`에 검증한 USD 단가를 함께 설정한다. 기본값은 미설정이다. 요청 당시 단가를 저장하므로 이후 단가 변경으로 과거 비용이 바뀌지 않는다. 실제 청구액·세금·환율은 계산하지 않는다.
- `AI_DAILY_BUDGET_USD`가 양수이면 한국 시간 요청 시작일 기준 예상비용 한도를 적용한다. 기본 `0`은 제한 미설정이다. 모델과 가격 설정이 맞지 않으면 제공자 호출을 차단한다. 관리자 API는 읽기 전용이며 설정 변경은 배포 환경변수로 수행한다. 여러 인스턴스는 동일한 단가·한도로 배포해야 한다.
- 호출 전에 입력 UTF-8 바이트 수·지시문·여유분 및 최대 출력 1,600토큰 기준 금액을 DB 잠금 안에서 예약한다. 완료 후 확인된 사용량으로 정산한다. 토큰을 확인하지 못한 타임아웃·전송 실패·중단은 예약액을 유지한다. 한도 도입 당일의 과거 요청에 비용과 예약액이 모두 없으면 추가 호출을 차단하며 다음 한국 날짜에 새 한도를 적용한다.
- 이 한도는 설정 단가와 보수적 토큰 추정에 따른 운영 제한이다. 실제 공급사 청구 상한을 보장하지 않으므로 OpenAI 프로젝트 예산 제한도 함께 사용한다. 성공률·실패율·근거 검사는 답변의 사실 정확도를 측정하는 지표가 아니며 실제 모델 품질 평가는 별도로 수행해야 한다.
- `GET /api/v1/admin/ai-consultations/usage/metrics`는 관리자 세션이 있어야 사용할 수 있다. 기존 일별 요청 API는 그대로 유지한다. 구현·CI 검증은 모의 제공자 응답만 사용하며 운영 유료 호출을 자동 활성화하지 않는다.

### 주택형별 필요 현금 계획

공고 상세의 `주택형별 필요 현금 계산기`에서 주택형을 선택하고 계약금·중도금 비율, 중도금 대출, 잔금 시 총 대출, 추가 비용과 현재 현금을 직접 입력하면 단계별 자기자금·누적 부족액을 확인할 수 있습니다. 공급금액은 수집된 주택형 최고 금액(원)을 사용하며 수정할 수 있습니다. 미확인 비율·대출·추가 비용은 자동 추정하지 않습니다.

중도금 대출은 잔금 때 상환하고 추가 비용은 잔금 단계에 더하는 계획입니다. 실제 납부일과 대출 가능 여부는 공식 공고·계약서·금융기관에서 확인해야 합니다. 입력·결과는 현재 상세 화면에서만 유지하며 서버·AI로 전송하지 않습니다. 임대 공고와 주택형 자료가 없는 공고에는 분양 계산을 적용하지 않습니다.

프런트 모듈 책임, 계산식·입력 제한, 검증·배포 절차는 [프런트 구조와 변경 안내](docs/frontend-architecture.md)를 참고하세요.

현금 계산 후 `비교에 담기`를 누르면 같은 공고의 계획을 최대 3개까지 비교할 수 있습니다. 입력이나 주택형을 바꿔도 담아 둔 계획은 당시 조건을 유지합니다. 같은 조건의 중복은 막으며 개별 삭제·전체 비우기를 지원합니다. 첫 계획 대비 자금 차이는 참고값이며 대출 가능 여부나 추천 순위가 아닙니다.

`현재 계산 파일 저장` 또는 `비교 내역 파일 저장`은 공급금액 출처, 모든 입력 가정, 단계별 결과·부족액, 계산 시각과 미반영 항목을 텍스트 파일로 내려받습니다. 비교는 상세 창을 닫으면 지워지고, 직접 내려받은 파일만 기기에 남습니다. 서버나 AI로 자금 정보를 전송하지 않습니다.

### 공고 상세 일정과 캘린더 저장

상세 화면의 `핵심 일정 타임라인`에서 특별공급·청약 접수·발표·계약 일정을 한국 날짜 기준으로 확인할 수 있습니다. 진행 중·오늘 종료·예정·종료를 표시하며, 미확인 날짜와 날짜 오류는 따로 안내합니다.

확인된 일정을 선택해 `선택 일정 저장 (.ics)`을 누르면 기기의 캘린더로 가져올 수 있습니다. 기간의 마지막 날까지 포함한 종일 일정이며 실제 시간·순위·계약 대상은 공식 공고를 확인하세요. 파일은 자동 갱신되지 않고 알림 시간은 캘린더 앱에서 설정합니다. 다시 가져오기 전 기존 일정을 확인해 중복을 방지하세요.

### 주택형 탐색과 비교

상세의 `주택형별 공급·분양가`에서 분양가·공급면적·공급 세대로 정렬하거나 현재 검색의 예산·면적 조건에 맞는 주택형만 볼 수 있습니다. 미확인 값은 정렬 마지막에 표시하며, 조건 일치는 같은 주택형의 예산과 면적을 함께 확인합니다. 전체 공급 요약은 필터와 관계없이 공고 전체를 기준으로 표시하고, 공급 세대가 일부 미확인이면 합계를 확정하지 않습니다.

같은 공고의 주택형을 최대 3개 선택하면 공급면적, 최고 분양가, 일반·특별·전체 공급 세대를 나란히 비교합니다. 먼저 선택한 주택형 대비 차이를 표시하며, 미확인 값은 0으로 계산하지 않습니다. 정렬·필터 변경 시 선택은 유지되고, 기준을 해제하면 다음 선택이 기준이 됩니다. 상세 닫기·공고 전환·새로고침으로 초기화되며 서버에 저장하지 않습니다. 공급면적은 전용면적과 다를 수 있고, 최고 분양가는 실제 동·호수 가격이나 대출 가능 여부를 뜻하지 않습니다.

### 공개 API 지연 진단

`node scripts/measure-public-api.mjs https://cheongyak-one-api.onrender.com`은 최초 health 응답과, 정상 응답 이후 목록·건수 조회 각 2회의 소요 시간을 순서대로 출력합니다. 최초 health 실패 시 후속 조회는 보내지 않습니다. 최대 5회 공개 GET이며 쿠키·인증정보·회원 데이터·동기화 호출을 사용하지 않습니다. 각 요청은 최대 15초이며 자동 재시도하지 않습니다.

이는 클라이언트에서 관측한 응답 시간입니다. 최초 요청이 실제 cold start인지, 네트워크·서버·DB 중 어디가 병목인지는 이 결과만으로 확정할 수 없고, 2회 표본으로 평균 성능이나 p95를 주장하지 않습니다. 로컬/CI 자동 검증은 모의 응답만 사용하며 운영 측정은 명시적으로 명령을 실행할 때만 진행됩니다.

목록 화면은 현재 탭의 첫 응답이 성공한 뒤 다른 상태 탭을 미리 읽습니다. 서버가 응답하지 않거나 실패한 동안에는 다른 탭의 사전 요청을 시작하지 않습니다. 기존 목록 캐시·요청 취소·자동 재시도는 유지합니다.
