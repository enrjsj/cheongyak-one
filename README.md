# 청약한눈

아파트, 공공임대, 오피스텔 청약 공고를 한곳에서 검색하고 일정과 핵심 자격을 확인하는 서비스입니다.

## 프로젝트 구성

    cheongyak-one
    ├── frontend   React + TypeScript + Vite
    └── backend    Java 21 + Spring Boot + JPA + PostgreSQL + Flyway

로컬에서는 프런트엔드와 백엔드를 각각 실행합니다. 운영에서는 React 정적 파일을 S3·CloudFront에, Spring Boot API를 Elastic Beanstalk에 분리 배포합니다.

AWS 운영 배포는 Elastic Beanstalk, RDS PostgreSQL, 비공개 S3, CloudFront, GitHub OIDC로 구성됩니다. 인프라 생성과 배포 순서는 [AWS 배포 가이드](docs/aws-deployment.md)를 참고합니다.

## 로컬 실행

### 프런트엔드

    cd frontend
    npm install
    npm run dev

기본 주소는 http://localhost:5173 이며 /api 요청은 http://localhost:8080 으로 전달합니다.

### 백엔드

PostgreSQL 연결 전에는 PostgreSQL 호환 모드의 H2 기반 local 프로필을 사용할 수 있습니다.

    mvn -pl backend spring-boot:run -Dspring-boot.run.profiles=local

운영과 유사한 PostgreSQL 환경에서는 .env.example을 참고해 환경변수를 등록하고 실행합니다.

    mvn -pl backend clean package
    java -jar backend/target/cheongyak-one-backend-0.1.0-SNAPSHOT.jar

## 데이터베이스 변경

- JPA는 ddl-auto=validate로 사용합니다.
- 테이블 생성과 변경은 backend/src/main/resources/db/migration의 Flyway SQL로 관리합니다.
- 이미 적용한 Migration 파일을 수정하지 않고 다음 버전 파일을 추가합니다.

## 일배치

- 기본 실행 시각: 매일 03:10 (Asia/Seoul)
- 최근 90일과 향후 365일 공고를 재조회합니다.
- 한국부동산원 청약홈 API에서 APT와 오피스텔 공고를 페이지 단위로 수집합니다.
- 마이홈포털 API 키가 설정된 환경에서는 공공임대 모집공고도 함께 수집합니다.
- 마이홈포털 API 키가 없으면 공공임대 수집만 건너뛰고 청약홈 APT·오피스텔 배치는 계속 실행합니다.
- 각 공고 소스는 기본 3회까지 재시도하며, 한 소스가 최종 실패해도 다른 소스의 수집과 저장은 계속합니다.
- 일부 소스만 실패한 실행은 관리자 운영 화면에 `부분 성공`으로 기록됩니다.
- 실행 이력은 SYNC_EXECUTION에 기록합니다.

GitHub Actions의 `CI / real-data` 작업은 Repository Secret인 `REB_API_KEY`를 환경변수로 주입합니다. PostgreSQL 구성 전에는 H2에 실제 공고를 저장하고 공개 데이터만 `reb-real-data-sample` 아티팩트로 출력합니다.

프런트엔드는 더 이상 예시 공고를 사용하지 않습니다. 백엔드의 `/api/v1/notices` 목록·상세 API를 호출하며, 개발 서버에서는 Vite 프록시가 `localhost:8080`의 Spring Boot로 요청을 전달합니다. 검색·지역·유형·상태·정렬은 서버에서 처리하고 프런트는 24건씩 다음 페이지를 요청합니다.

상세 API는 목록용 요약 응답과 분리되어 공급 구분, 입주 예정월, 특별공급·계약 일정, 사업주체, 시공사, 문의처, 분양 홈페이지를 추가로 제공합니다. 외부 API의 링크는 HTTP·HTTPS 주소만 저장합니다.

### 공고 검토 기능

- 공고를 최신 공고순 또는 마감 임박순으로 정렬할 수 있습니다.
- 최대 3개 공고를 지역·일정·가격·공급 규모 기준으로 비교할 수 있습니다.
- 비교 목록은 브라우저에 저장되며 URL의 `compare` 값으로 공유할 수 있습니다.
- 로그인 회원의 비교 목록은 계정에 저장되어 다른 기기에서도 이어서 확인할 수 있습니다.
- 로그인할 때 현재 브라우저 또는 공유 링크의 비교 목록을 계정 목록과 합치며 최대 3개를 유지합니다.
- 관심 공고 또는 비교 공고의 접수 시작·마감·당첨 발표 일정을 `.ics` 파일로 저장할 수 있습니다.
- 상세 공고 URL을 복사해 공유할 수 있으며 직접 접속·새로고침·브라우저 뒤로가기로 상세 화면 상태를 복원합니다.
- 최근 확인한 공고 5건을 브라우저에 보관해 홈에서 빠르게 다시 열 수 있으며 언제든 전체 삭제할 수 있습니다.
- 검색어·상태·지역·주택유형·정렬 조건을 URL로 공유하고 새로고침이나 브라우저 탐색 후에도 복원합니다.
- 캘린더 파일은 브라우저에서 생성하며 서버로 개인 일정을 전송하지 않습니다.

### 회원 기능

- 이메일 회원가입과 HttpOnly 세션 쿠키 기반 로그인을 지원합니다.
- 회원가입은 계정 정보와 맞춤 정보의 2단계 화면으로 구성되며, 생년월일·성별·혼인 상태·가구원 수·자녀 수·거주 지역을 선택 입력할 수 있습니다.
- 맞춤 정보는 별도 수집·이용 동의가 있을 때만 저장하며 공고 추천, 자격 사전점검 보조, 서비스 이용 통계 및 추천 품질 개선에 사용합니다. 동의 시점과 문구 버전을 기록하고, 계정 화면에서 닉네임과 계정은 유지한 채 선택정보와 동의 이력만 즉시 삭제할 수 있습니다.
- 성별은 추천 점수나 청약 자격 판정에 사용하지 않으며, 관리자 회원 통계에서 동의 회원의 연령대·혼인 상태·거주 지역·가구원·자녀 수와 함께 집계값으로만 제공합니다. 관리자 회원 목록에는 개인별 맞춤정보를 노출하지 않습니다.
- 선택형 맞춤 정보는 회원 관리 화면에서 수정·삭제할 수 있고, 거주 지역은 검색 지역을 별도로 지정하지 않았을 때 추천 점수의 보조 신호로만 사용합니다.
- 이메일 인증 링크는 24시간 동안 한 번만 사용할 수 있으며, 인증 전 로그인은 차단됩니다.
- 비밀번호 재설정 링크는 30분 동안 한 번만 사용할 수 있고 완료 시 모든 기기에서 로그아웃됩니다.
- 인증·재설정 토큰은 원문 대신 SHA-256 해시만 DB에 저장하며 재요청에는 2분 제한을 둡니다.
- 비밀번호는 BCrypt로 저장하고, 5회 연속 실패하면 10분 동안 로그인을 잠급니다.
- 닉네임·비밀번호 변경, 로그아웃, 회원 탈퇴를 지원합니다.
- 로그인 전 브라우저에 저장한 관심청약은 첫 로그인 시 계정 목록과 합쳐집니다.
- 비밀번호 변경과 탈퇴 시 모든 기기의 로그인 세션을 폐기합니다.
- 회원관리에서 로그인한 브라우저·운영체제와 로그인 시각을 확인하고 다른 기기를 개별 또는 일괄 종료할 수 있습니다.
- 계정당 활성 로그인은 최근 10개로 제한하며, 초과 시 가장 오래된 세션부터 종료합니다.
- 기기 관리에는 IP 주소를 저장하지 않으며, 회원가입과 비밀번호 변경 화면에서 비밀번호 확인을 검증합니다.
- 탈퇴한 회원의 개인정보와 맞춤 프로필은 제거·익명화하고 관심청약은 삭제합니다.
- 상태 변경 요청은 세션별 CSRF 토큰으로 검증합니다.

### 맞춤 검색조건

- 로그인 회원은 지역·주택유형·공고상태·정렬 조건을 계정에 저장할 수 있습니다.
- 저장한 조건은 로그인 시 자동으로 적용되며 다른 기기에서도 불러올 수 있습니다.
- 필터 화면에서 현재 조건으로 덮어쓰거나 저장 조건을 삭제할 수 있습니다.

### 관심청약 알림

- 관심청약의 접수 시작일, 마감 7일·3일·1일 전, 당첨자 발표일 알림을 제공합니다.
- 알림 생성 작업은 기본적으로 매시 5분에 실행되며 같은 일정의 알림은 중복 생성하지 않습니다.
- 헤더 알림함에서 미읽음 개수 확인, 개별 읽음, 모두 읽음과 공고 상세 이동을 지원합니다.
- 회원별로 받을 일정 종류를 설정할 수 있고, 관심 해제 시 해당 공고 알림도 삭제됩니다.
- 저장한 지역·주택유형·접수상태에 맞는 신규 공고도 관심 등록 전부터 알림으로 받을 수 있습니다.
- 관심 등록한 공고의 일정·주소·공급 규모·문의처 등 주요 정보가 바뀌면 변경 알림을 받을 수 있습니다.
- 상세 화면에는 최근 변경 시각과 변경 항목을 함께 표시해 다시 확인할 부분을 바로 알 수 있습니다.
- 변경 기록은 최근 20건까지 시간순으로 보관해 상세 화면에서 확인할 수 있습니다.
- 공고의 최초 수집 시각을 별도로 보존해 이후 정보 갱신 때 신규 공고 알림이 반복되지 않습니다.
- 회원이 직접 동의하면 인증한 이메일로도 선택한 일정·신규 공고 알림을 발송합니다. 기본값은 수신 안 함입니다.
- 이메일 발송 상태는 DB에 저장하며 실패 시 1·2·4·8·16분 간격으로 최대 5회 재시도합니다.
- 읽은 지 90일이 지난 알림은 자동 삭제합니다.
- 로그인 중에는 헤더의 미읽음 개수를 1분마다 갱신하고, 열린 알림함은 30초마다 자동 갱신합니다.
- 알림함에서 마지막 확인 시각과 수동 새로고침을 제공합니다.

### 접근성 및 모바일 사용성

- 모달을 열면 키보드 포커스를 내부에 유지하고 `Escape`로 닫을 수 있습니다.
- 모달을 닫으면 열기 버튼으로 포커스가 돌아가며 열린 동안 배경 화면 스크롤을 잠급니다.
- 키보드 포커스 표시, 모바일 터치 영역과 동적 화면 높이·안전 영역을 지원합니다.

### 맞춤 청약 추천

- 회원이 저장한 지역·주택유형·접수상태를 기준으로 접수 예정·접수중 공고를 추천합니다.
- 조건 일치도와 접수 시작·마감 임박도를 점수화하고 추천 이유를 함께 표시합니다.
- 추천 결과는 최대 6건이며 마감된 공고와 저장 조건에 맞지 않는 공고는 제외합니다.
- 저장 조건이 없거나 결과가 없으면 조건을 설정하거나 넓힐 수 있도록 안내합니다.
- 추천 점수는 검색 편의를 위한 값이며 실제 청약 자격 판정 결과가 아닙니다.
- 원하지 않는 공고는 추천에서 숨길 수 있고, 계정에 저장된 숨김 목록을 한 번에 초기화할 수 있습니다.
- 숨긴 공고를 관심청약으로 저장하면 최신 선택을 우선해 추천 숨김 상태가 자동 해제됩니다.

### 청약 조건 사전점검

- 무주택 세대, 청약통장, 신혼부부·생애최초 공급에 관한 답변을 바탕으로 공식 공고문에서 확인할 항목을 정리합니다.
- 알지 못하는 항목은 추측하지 않고 `잘 모르겠어요`로 답할 수 있습니다.
- 신청 가능·불가능을 판정하거나 보장하지 않으며 저장 버튼을 누르기 전에는 답변을 서버로 전송하지 않습니다.
- 로그인 회원은 답변을 계정에 저장하고 다른 기기에서 조회·수정하거나 삭제할 수 있습니다.

### 관리자 운영 현황

- `ADMIN` 역할의 회원은 최근 공고 동기화 50건의 성공·실패·실행중 상태를 확인할 수 있습니다.
- 조회·저장 건수, 실행시간, 24시간 실패 건수와 최근 성공 시각을 제공합니다.
- 오류 메시지에 포함될 수 있는 API 키·토큰 형태는 화면 응답 전에 마스킹합니다.
- 회원 관리 탭에서 이메일·닉네임 검색, 이용/정지/탈퇴 상태 필터와 이메일 인증·활성 세션·로그인 잠금 상태를 확인할 수 있습니다.
- 로그인 잠금 초기화와 전체 기기 강제 로그아웃을 지원하며, 관리자가 자신의 현재 계정 세션을 실수로 강제 종료하는 동작은 차단합니다.
- 일반 회원의 이용정지·해제를 지원합니다. 정지 즉시 모든 세션·계정 작업 토큰·대기 알림 메일을 폐기하며 관리자 계정은 화면에서 정지할 수 없습니다.
- 이용정지 사유는 200자 이내로 필수 입력하고 감사 로그에서 확인할 수 있습니다.
- 잠금 초기화와 강제 로그아웃은 처리자·대상·처리 건수와 함께 감사 로그로 저장하며 최근 100건을 운영 화면에서 확인할 수 있습니다.
- 관리자 역할은 이메일 인증이 완료된 계정을 확인한 뒤 운영 DB에서 직접 부여합니다.

    # 터미널 1: 실제 데이터가 포함된 백엔드 실행
    export REB_API_KEY="발급받은 개발키"
    mvn -pl backend clean package
    java -jar backend/target/cheongyak-one-backend-0.1.0-SNAPSHOT.jar \
      --spring.profiles.active=local \
      --app.notice-sync.run-on-startup=true

    # 터미널 2: 프런트엔드 실행
    cd frontend
    npm ci
    npm run dev

`http://localhost:5173`에서 실제 아파트·오피스텔 공고, 상태별 건수, 지역·주택유형 필터, 상세 공고 링크를 확인할 수 있습니다.

로컬에서 실제 데이터 배치를 한 번 실행하려면 `REB_API_KEY` 환경변수를 설정한 후 아래 명령을 사용합니다.

    mvn -pl backend clean package
    java -jar backend/target/cheongyak-one-backend-0.1.0-SNAPSHOT.jar \
      --spring.profiles.active=local \
      --spring.main.web-application-type=none \
      --app.notice-sync.run-on-startup=true

## 환경변수

실제 DB 비밀번호와 API 키는 Git에 커밋하지 않습니다.

| 이름 | 설명 |
|---|---|
| DB_URL | PostgreSQL JDBC URL |
| DB_USERNAME | 애플리케이션 DB 계정 |
| DB_PASSWORD | 애플리케이션 DB 비밀번호 |
| REB_API_KEY | 한국부동산원 청약홈 API 키 |
| MYHOME_API_KEY | 마이홈포털 API 키 |
| NOTICE_SYNC_CRON | 공고 동기화 실행 시각 |
| MEMBER_NOTIFICATION_CRON | 관심청약 알림 생성 시각(기본: 매시 5분) |
| MEMBER_NOTIFICATION_EMAIL_CRON | 대기 중인 알림 이메일 발송 시각(기본: 5분마다) |
| MEMBER_MAIL_DELIVERY | 회원 메일 전달 방식(`log`, `smtp`, `disabled`) |
| MEMBER_EMAIL_VERIFICATION_REQUIRED | 신규 회원 이메일 인증 필수 여부 |
| FRONTEND_BASE_URL | 인증·재설정 링크에 사용할 프런트 주소 |
| MEMBER_MAIL_FROM | 발신 이메일 주소 |
| SMTP_HOST / SMTP_PORT | SMTP 서버 주소와 포트 |
| SMTP_USERNAME / SMTP_PASSWORD | SMTP 자격정보 |

로컬 기본값은 `log`이며 인증·재설정 링크가 백엔드 로그에 출력됩니다. 실제 운영에서는 SMTP 설정을 완료하기 전까지 AWS 프로필의 인증 필수 기본값이 꺼져 있습니다.
