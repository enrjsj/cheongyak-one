# 작업 체계 결정

## 2026-10-08: 관련 검사와 최종 전체 검증 분리

- 사용자 요청에 따라 수정 중에는 관련 단위/브라우저/백엔드 검사만 실행하고, 수정과 기록을 모은 고정 통합본에서 최종 전체 검증한다.
- 실패 원인 분석은 해당 검사·로그부터 시작한다. 전체 테스트, 기록용 커밋, CI·배포를 수정마다 반복하지 않는다.
- 문서만 변경하면 로컬 docs 검증으로 마무리한다. 앱 변경의 full, UI/모바일·인증의 extended, PostgreSQL 별도 경로와 필수 CI는 유지한다.
- 문서 정책을 바꾸며 하네스 구현·CI 트리거·검증 기준·재시도 횟수·배포 설정은 변경하지 않는다. 실행 대상 SHA/범위와 재시도·미검증은 구분해서 보고한다.

## 2026-10-07: 저장소 기반 하네스

- Codex 자체 런타임을 새로 만들지 않고, 기존 Codex에 프로젝트 규칙·테스트 진입점·검증 증거를 제공한다.
- `AGENTS.md`는 짧은 진입점으로 유지한다. 상세 기능 설명은 기존 문서에 둔다.
- 새 의존성 없이 Node 스크립트로 Windows/Unix 공통 명령을 제공한다.
- 작업 중 commit/push/PR/CI 반복을 하지 않는다. 원격 반영은 사용자 요청 시 별도 단계로 수행한다.
- 검증은 변경 영역에 따라 선택하되 명시적 `full`로 확대할 수 있다. 테스트 생략을 성공으로 표현하지 않는다.
- 하네스 보고서는 로컬 `.harness/`에 저장하고 Git에서 제외한다. 작업 종료 시 요약만 HANDOFF에 남긴다.
- 스크립트는 Git 쓰기·배포·외부 유료 API·운영 DB를 실행하지 않는다. 환경 격리는 실수 방지 장치이며 OS 샌드박스를 대체하지 않는다.
- CI에는 빠른 하네스 자체 테스트/규칙 검사만 추가하고 기존 프로젝트 테스트 job은 중복 실행하지 않는다.

## 2026-10-07: 자동 분업 규칙 통합

- 작업마다 단일/멀티를 되묻지 않고 독립성·검토 이득에 따라 총괄이 판단한다. 작은 수정·순차 의존은 단일, 독립 구현이나 검토는 분업한다.
- Codex 기본 서브에이전트와 로컬 역할 TOML을 사용하며 별도 상시 서버나 스케줄러는 만들지 않는다.
- 하위 동시 한도 3명, 모델·추론 상속, 재귀 위임 금지. 런타임의 더 낮은 한도와 상위 정책이 우선이다.
- writer는 별도 worktree/소유 경로와 미커밋 snapshot을 전달받는다. 총괄이 공유 파일·통합·고정 포트 테스트를 맡고 reviewer는 읽기 전용으로 검토한다.
- 호스팅 도구의 실제 분업과 사용자 PC의 TOML 로딩은 별도로 검증한다. 설정 구문 검사만으로 자동 로딩·인원 제한 적용을 주장하지 않는다.
- 다른 환경의 `60fda31` 기준 설정을 `fc51550`에 선별 통합하며 PR #125/#127 기록과 진행 중 공급기관 집계 변경을 보존한다. 전역 설정·신뢰·승인·네트워크 정책을 변경하지 않는다.
