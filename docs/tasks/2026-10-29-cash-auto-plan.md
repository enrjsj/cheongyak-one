# 분양가·준비 현금 기반 간편 계획

- 기준: `5809ed6b2a175d295e54471294fd8c18b27f157f` (PR #146), clean main에서 `codex/cash-payment-preview`.
- 사용자 요청: 납부 비율을 자동 적용하고 선택 분양가와 준비 현금만 입력하면 나머지를 계산.
- 목표: 기본 간편 화면에서 예시10/60/30·단계별 공급대금·현금 배분·추가 자금을 즉시 확인. 비율 수정과 대출/비용 상세 계산 유지.
- 제외: 공식 공고 PDF 추출, 대출 승인/한도/금리/세금 추정, API/DB/회원/배포 설정 변경, 실제 금융·알림 호출.
- 담당: 총괄 구현·공유 문서·테스트 포트 전부 소유. AGENTS auto 판단으로 `/root/cash_plan_review`가 별도 읽기 리뷰, 파일 쓰기/테스트 실행/재위임 없음.

## 계약과 구현

- 현재 REB 매핑/DB/API에는 최고 공급금액·계약 기간만 있으며 공식 납부 비율은 없음. 외부 원본 API의 추가 필드 여부는 별도 조회하지 않음.
- 예시 비율을 공고 확정값과 구분하고 직접 조정/예시 복원을 제공. 사용자 비율 편집은 `user`, 예시 적용은 `example`; 상세 snapshot·비교·파일에도 출처를 보존.
- `calculatePaymentSchedule`로 분할 계산을 공유, 정수원/BigInt 절사와 잔금 차액 보존 유지. `calculateSimpleCashPlan`은 현금을 앞 단계부터 순차 배분해 중복 사용하지 않음.
- 6억/현금1억 예시: 납부6천만·3.6억·1.8억, 현금배분6천만·4천만·0, 추가자금0·3.2억·1.8억, 누적0·3.2억·5억. 초과 현금은 납부 후 잔여액으로 표시.
- 간편에서 대출/비용을0원으로 만들어 상세 계산하지 않는다. 별도 공급대금 계획이며 해당 항목 미반영/부족액은 대출 승인액 아님을 명시. 입력 중 초점을 빼앗지 않음. 빈값·오류 시 과거 수치 제거.
- 모드 전환은 입력/비교 snapshot 보존·기존 상세 결과 제거. 간편 주택형 변경은 준비 현금만 보존해 새 분양가에 적용, 비율 예시 복원/상세대출 초기화. 입력 초기화/닫기는 현금도 초기화.
- 독립 리뷰에서 비율 오류가 접힌 조정 영역에 숨는 경로 발견. 오류일 때 펼친 상태 유지, ARIA 확장 상태 동기화와 상세→간편/접기 회귀를 추가.
- 후속 리뷰에서 오류 수정 첫 글자가 유효해지면 조정 영역이 닫히는 경로를 발견. 비율 편집 시 펼침 상태를 유지하고 `selectText`+`pressSequentially('50')`로 값/보임/초점 유지 확인. `fill()`만으로 검증하지 않았다.
