## 동작

- GitHub Actions UTC cron으로 매일08:53·08:58 KST 예열,09:03~17:58 5분마다 실행(총110회/일). 정각 부하를 피하도록 분을 분산한다.
- 고정 Render 공개 `/actuator/health`만 인증정보 없이 GET한다. HTTP200과 JSON `status=UP`을 모두 확인한다. 응답 본문·예외 내용은 로그에 남기지 않는다.
- 기동 중 실패는 요청당20초/간격10초/전체4분으로 제한한다. 헤더·본문 대기 모두 취소 가능하다. 작업 전체 제한6분, 동시작업1개, 기존 공고 수집과 별도 concurrency.
- 실제 실행시각이08:50 이전 또는18시 이후면 수동실행도 호출 없이 skip한다.18시 전 시작한 요청도 남은 시간으로 timeout을 줄인다.18시 이후에는 상태 확인을 멈출 뿐 서버를 강제 종료하지 않는다.
- main에서만 실행하고 저장소 읽기 권한만 사용한다. 추가 Secret/유료 스케줄 서비스 불필요. main 반영 전에는 예약 실행되지 않는다.
- GitHub 예약 지연·누락·장기 비활성 저장소의 예약 중단과 Render 무료 사용량 제한이 있어09시 정각 준비/항상 켜짐을 보장하지 않는다. Actions 실행 기록과 JSON 결과로 실패/skip을 구분한다.
