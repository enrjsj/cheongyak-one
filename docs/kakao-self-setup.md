# 카카오톡 나에게 보내기 설정

이 기능은 정식 알림톡이 아니다. 지정된 청약한눈 회원 한 명이 연결한 카카오 계정의 **나와의 채팅방**으로 보낸다. 비즈니스 채널·알림톡 발송 업체·승인 템플릿은 사용하지 않는다. 앱 설정과 사용자의 최초 카카오 로그인/메시지 동의는 필요하다.

## 1. 카카오 디벨로퍼스에서 준비

1. 앱을 만들고 카카오 로그인을 활성화한다. 개발 단계에서는 본인 카카오 계정이 앱 소유자 또는 팀원인지 확인한다.
2. 카카오 로그인 동의항목에서 **카카오톡 메시지 전송 (`talk_message`)**을 사용할 수 있도록 설정한다. 실제 동의는 청약한눈의 연결 버튼으로 받는다.
3. REST API 키를 확인한다. Client Secret을 활성화했다면 함께 준비한다. 지도용 JavaScript 키를 이 기능에 넣지 않는다.
4. 카카오 로그인 **Redirect URI**를 정확하게 등록한다.

   ```text
   https://cheongyak-one-five.vercel.app/api/v1/members/me/kakao-self/callback
   ```

5. 메시지 링크의 웹 도메인으로 `https://cheongyak-one-five.vercel.app`을 등록한다. 개발자 콘솔의 [앱] → [제품 링크 관리] → [웹 도메인]에서 등록한다.

콜백은 웹(Vercel) 주소를 사용한다. `/api` rewrite가 Render로 전달하며, 웹에 로그인한 회원 세션 쿠키로 본인임을 검증한다. Render 주소로 직접 콜백을 등록하면 웹의 host-only 로그인 쿠키가 전달되지 않는다. 임의의 리다이렉트 주소는 허용하지 않는다.

로컬에서는 웹 주소를 `http://localhost:5173`, Redirect URI를 `http://localhost:5173/api/v1/members/me/kakao-self/callback`으로 맞추고 같은 호스트로 로그인한다. `localhost`와 `127.0.0.1`을 섞지 않는다. 로컬 프로필의 JPA create-drop만으로 신규 JDBC 테이블은 만들어지지 않으므로, 활성화 시험에는 Flyway V39까지 적용한 별도 개발 DB가 필요하다.

공식 문서: [카카오 로그인 REST API](https://developers.kakao.com/docs/ko/kakaologin/rest-api), [카카오톡 메시지 REST API](https://developers.kakao.com/docs/ko/kakaotalk-message/rest-api).

## 2. Render 서버 환경변수

Render → 청약 API 서비스 → Environment에 입력한다. **Vercel의 `VITE_*`에는 비밀값을 넣지 않는다.** 이 기능에 새 프런트 환경변수는 없다.

| 이름 | 값/용도 |
| --- | --- |
| `KAKAO_SELF_ENABLED` | 준비 완료 후 `true`. 기본 `false` |
| `KAKAO_SELF_OWNER_MEMBER_ID` | 본인의 **청약한눈 회원 숫자 ID**. 카카오 앱 ID/이메일/카카오 회원 ID가 아님 |
| `KAKAO_SELF_REST_API_KEY` | 카카오 앱 REST API 키 |
| `KAKAO_SELF_CLIENT_SECRET` | 카카오 로그인 Client Secret. 활성화하지 않은 경우 공란 |
| `KAKAO_SELF_REDIRECT_URI` | 위에 등록한 웹 주소의 콜백 URL 전체 |
| `KAKAO_SELF_TOKEN_ENCRYPTION_KEY` | 안전하게 생성한 32바이트 난수의 Base64 문자열. DB 토큰 암호화용 |
| `FRONTEND_BASE_URL` | `https://cheongyak-one-five.vercel.app`. 기존 이메일 링크에도 쓰이는 설정 |

회원 ID는 청약한눈에 로그인한 브라우저에서 개발자 도구 Network의 `/api/v1/members/me` 응답 `id`로 확인할 수 있다. 암호화 키는 로컬 비밀 관리 도구로 생성하고 서버 Secret에 저장한다. 키를 바꾸면 저장된 카카오 토큰을 해독할 수 없어 다시 연결해야 한다. 어떤 키/토큰/쿠키도 Git이나 대화에 붙여넣지 않는다.

DB에 V39 migration이 적용되고 설정이 유효해야 기능을 켤 수 있다. 활성화 상태에서 누락·잘못된 설정은 서버 시작을 실패시킨다. 운영 설정 변경·실발송은 구현 검증과 별도로 진행한다.

## 3. 본인 계정 연결과 시험

1. 지정한 청약한눈 계정으로 로그인 → 상단 **알림** → **알림 설정**.
2. **카카오톡 나에게 보내기 → 카카오 계정 연결** 선택 → 본인 카카오 로그인 → 메시지 전송 동의.
3. 돌아온 화면에서 서버가 확인한 **연결됨**을 확인한다.
4. **나에게 시험 메시지 보내기**를 눌러 나와의 채팅방을 확인한다. 1분 이내 중복 시험은 서버에서 제한한다.

다른 회원에게는 연결 기능이 표시되지 않으며, API도 지정된 본인 이외의 요청을 거부한다. 연결 버튼은 미저장 알림 설정이 있으면 잠기므로 먼저 설정을 저장한다.

## 발송 범위와 제한

- 공고 × 선택한 알림 일정마다 메시지를 따로 보낸다. 같은 공고도 접수 시작/마감 7·3·1일 중 켜둔 시점마다 발송될 수 있다. 지역·예산·평수 검색조건과 저장 조건 신규 공고 알림은 현재 카카오 발송 조건이 아니다.
- 메시지에 공고명, 공고 전체 금액 범위, 공급면적(㎡/약 평), 알림 종류와 일정 및 공고 링크를 담는다. 공공임대 금액은 임대보증금, 그 외 임대는 공고 금액, 일반 분양은 분양가로 표시한다. 억원은 소수 둘째 자리 반올림으로 약 표시하며 월 임대료·세금 등 추가비용/총 필요자금은 추정하지 않는다. 주택형 면적이 없으면 제목 등에서 추측하지 않고 공고문 확인으로 표시한다. 금액·면적은 각각 공고 전체 범위이며 특정 평형의 확정 가격을 뜻하지 않는다.
- 기존 알림 생성기가 만든 본인의 관심 공고 **접수 시작/마감 7일·3일·1일 전** 알림만 보낸다. 현재 관심 등록 및 알림 유형 설정을 발송 직전에 다시 확인한다.
- 최초 연결/재연결 이전 알림을 몰아서 보내지 않는다. 발송일의 한국 날짜에 생성된 알림만 대상이다. 당첨 발표/신규 매칭/공고 변경은 이번 카카오 발송 범위에서 제외하며 기존 알림함 기능은 유지한다.
- 서버 실행 중 5분 주기로 대상을 확인한다. 알림 생성 주기와 무료 Render 절전으로 늦어질 수 있다. 절전 중에는 스케줄러가 돌지 않으며 정시 발송·모든 일정 도착을 보장하지 않는다.
- DB에 시도를 먼저 기록한다. 카카오 응답이 끊기거나 서버가 종료되면 실제 도착 여부가 불명확하므로 **자동 재발송하지 않는다**. 누락 가능성과 중복 방지 사이에서 중복 방지를 우선한 1차 정책이다. 화면의 최근 발송 접수는 카카오 API 수락을 뜻하며 기기 수신 확인은 아니다.
- 액세스 토큰을 서버에서 갱신한다. 갱신 토큰 만료/동의 철회 시 **다시 연결 필요**를 표시한다. 갱신 응답에 새 refresh token이 없으면 기존 값을 보존한다.
- **카카오 발송 연결 해제**는 서비스에 저장한 토큰을 지우고 후속 발송을 중단한다. 이미 카카오에 접수된 메시지는 취소할 수 없다. 카카오 앱 동의 자체의 철회는 카카오 계정에서 별도로 한다. 청약한눈 탈퇴 시에도 저장 토큰을 제거한다.
- 정식 알림톡 설정이나 기존 이메일/앱 푸시 설정과 독립적이다. 운영 키와 실제 사용자 동의 없이 로컬 테스트는 모의 카카오 응답만 사용한다.
